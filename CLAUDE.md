# Development Notes

## Architecture

### Shared Components (`js/components.js`)
Several sections are generated by `js/components.js` and injected into placeholder elements. This keeps them uniform across the site — edit the component in JS, not in individual HTML files.

**Header & Footer** — injected into `<div id="site-header">` and `<div id="site-footer">`
- Auto-detects page depth (`/products/`, `/bespoke-pages/`) for correct relative paths
- Auto-applies the active nav class based on the current page filename
- Loaded synchronously in `<head>` to prevent flash; fires a `componentsLoaded` event for `main.js`
- `components/` folder files are reference copies, not loaded at runtime

**Bespoke Teaser CTA** — injected into `<div id="bespoke-teaser">`
- Heading is always "Looking for something bespoke?"
- Per-page content set via data attributes: `data-body`, `data-btn-text`, `data-btn-href`
- Default button links to `trade.html`
- Used on: `index.html`, `collections.html`, `bespoke.html`

**Contact Block** — injected into `<div id="contact-block">`
- Split layout with contact details + Google Maps (cookie-gated) embed
- Email, phone, and map are hardcoded in the component
- Per-page content set via: `data-heading`, `data-body`, `data-btn-text`
- Used on: `about.html`, `trade.html`, `contact.html`

**Carousel** — injected into `<div class="carousel-component">`
- Generates the full `.carousel-wrapper` with prev/next SVG buttons and `.carousel-track`
- Items passed as JSON via `data-items` attribute: `[{"img":"...","alt":"...","label":"...","href":"..."}]`
- Items with `href` render as `<a>` tags and get hover effects; without `href` render as `<div>` tags with no hover
- Used on: `index.html`, `about.html`, `bespoke.html`, `trade.html`
- The Instagram carousel on `index.html` is NOT a component (uses different card markup)
- `bespoke.html` and `trade.html` carousels link to individual product pages in `products/`

### JavaScript
- `js/main.js` — all interactive behaviour (carousel, mobile menu, scroll effects, product gallery, stockists map, reveal animations, catalogue filter). Wrapped in an `init()` function that waits for `componentsLoaded`
- `js/components.js` — shared component generation and injection (header, footer, bespoke teaser, contact block, carousel)

### CSS
- Single stylesheet: `css/styles.css`
- Uses CSS custom properties for spacing:
  - `--section-pad: 80px` (desktop section padding)
  - `--section-pad-mobile: 48px` (mobile section padding)
  - `--grid-gap: 24px` (grid/card gaps)

### Responsive Breakpoints
- Desktop: default styles
- Tablet: `max-width: 1024px`
- Mobile: `max-width: 768px`

## Key Conventions

### Homepage Hero
- Desktop: 720px height, overlay layout (text over image with gradient)
- Tablet: 520px height
- Mobile: auto height, **stacked layout** — text on top (order: 1), image below (order: 2), white gradient blending them via `::before` pseudo-element on `.hero picture`. Never use overlay on mobile.

### Spacing
All section padding should use CSS variables, not hardcoded values:
- Page-hero desktop: `calc(var(--section-pad) * 1.5)` top / `var(--section-pad)` bottom
- Page-hero tablet: `calc(var(--section-pad) * 1.25)` top / `calc(var(--section-pad) * 0.8)` bottom
- Page-hero mobile: `var(--section-pad)` top / `var(--section-pad-mobile)` bottom

### Hover States
Hover effects are only applied to elements that are genuinely interactive (links, buttons). Non-clickable elements — feature blocks, process steps, path cards, stockist cards — have no hover. This is intentional to avoid misleading users into expecting interaction.

For carousels specifically, only `a.carousel-card` (items with `href`) gets hover styles. The hover uses `filter: drop-shadow()` (not `box-shadow`) because `box-shadow` is clipped by `.carousel-track`'s `overflow: auto`. The image zoom (`transform: scale`) works because `.card-image` has `overflow: hidden` which contains it independently.

### Mobile Carousel
The `.carousel-wrapper` uses `margin-right: -20px` to extend past container padding, with `padding-right: 20px` on the track. This prevents cards being clipped at the screen edge.

`.carousel-track` has `padding: 20px 0` (vertical) to give `filter: drop-shadow` hover effects room to render without being clipped by the track's overflow.

## Bespoke Catalogue Pages

### Category pages (`bespoke-pages/`)
- Each page (`bespoke-castles.html`, `bespoke-cathedrals.html`, `bespoke-museums.html`, `bespoke-animals.html`) has its own heading and intro, and a sub-filter dropdown using `data-subcategory` on cards + JS in `main.js`
- Product cards link to `../products/product-{slug}.html` and carry `data-subcategory="{value}"` for JS filtering

### All-products page (`bespoke-pages/bespoke-all.html`)
- Shows all bespoke products in one grid (163 after removing placeholder cards)
- Filter dropdown uses category names as values (`cathedrals`, `castles`, `museums`, `animals`) — NOT page filenames
- Cards carry `data-subcategory="{category}"` matching those values
- When the filter changes, JS in `main.js` updates the `<h1>` and `.catalogue-intro` text to match the selected category (copy is stored in the `categoryContent` object in `main.js`)
- 2 products have no images and remain as non-linked cards (`href="#"`)

### Product pages (`products/`)
- ~162 files following the pattern `product-{slug}.html`
- Product images live at `assets/images/products/{slug}-1.jpg` (front) and `{slug}-2.jpg` (back)
- No back-navigation bar — user relies on the browser back button
- `.product-detail` section has `padding: 80px 0 80px` (top padding accounts for the removed back bar)
- Stockist location shown via **Leaflet.js** map (not Google Maps/OSM iframe). Map div uses `data-lat` and `data-lng` attributes; `main.js` initialises the map and calls `invalidateSize()` after 100ms. Leaflet CSS and JS must be loaded in `<head>` before `components.js`. Map container requires an explicit `height` (not `aspect-ratio`) for Leaflet to render tiles correctly.
- Buy links (where applicable) are appended directly to the `.product-description` paragraph

### Commission Process section
- Used on both `bespoke.html` (white background) and `trade.html` (mist-blue background)
- Base class `.commission-process` keeps the mist-blue background and scallop wave decorators
- Add modifier `.commission-process--white` on `bespoke.html` only to override to white and suppress the waves
- Never change the base class styles — it will break the trade page

## Naming

"Exclusives" was renamed to **"Bespoke"** across the site (April 2026):
- Files: `bespoke.html`, `bespoke-pages/bespoke-*.html`
- Nav and visible text all say "Bespoke"
- **CSS class names still use `exclusives`** (e.g. `.exclusives`, `.exclusives-intro`) — this is intentional to avoid breaking styles

## File Structure
```
index.html              — Homepage
about.html              — About page
collections.html        — Collections page (includes Leaflet map)
bespoke.html            — Bespoke decorations catalogue
trade.html              — Trade/wholesale page
contact.html            — Contact us page (page hero + contact block component)
bespoke-pages/          — Bespoke sub-category pages
products/               — Individual product pages (~162 files)
scripts/                — One-off utility scripts (e.g. convert-to-leaflet.py)
components/             — Reference HTML templates (not loaded at runtime)
css/styles.css          — Single stylesheet
js/components.js        — Shared header/footer/component generator
js/main.js              — All interactive behaviour
assets/                 — Images and static assets
```
